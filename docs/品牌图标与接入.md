# 品牌图标与接入（EmoReply / AIMsg）

> 合并自 `t01163-logo-result.md`（logo 与全套资产设计）与 `t01164-icon-integration-result.md`（三端接入与打包验证）。
> 资产根目录：`D:/code/otherProjects/28_AIMsg/brand/`（含 `brand/README.md` 设计规范）。
> 图形生成：Agnes Image 2.5 Flash 文生图筛选 → 程序化去背/重采样/ICO-ICNS 打包 → 手写矢量重绘。

## 1. 根因

项目此前**没有任何品牌标识资产**：

- `android-app` 未声明 `android:icon`，安装后是系统默认绿机器人图标；`res/` 下无 `mipmap-*`。
- `desktop-app/package.json` 无图标配置，`main.js` 创建 `BrowserWindow` 未传 `icon`，任务栏为 Electron 默认图标。
- 安装包（exe/APK）、界面、托盘、应用商店均无可用的统一标识。

目标：专业视觉识别度、兼容 16px–512px，提供矢量源 + 多尺寸位图 + ICO + 单色变体 + 完整规范。

## 2. 定稿图形与语义

超椭圆徽标（深蓝 `#08275E` → 青 `#21AFAF` 竖向渐变）+ 白色对话气泡（尾巴在左下）+ 气泡内浅蓝爱心 `#8DB9D5` + 右上淡青星光 `#C5FEF5`。

语义：气泡＝聊天场景，爱心＝高情商/共情（产品差异点），星光＝AI 生成。三稿中选取第三稿——元素最少、语义最准、深底浅图在小尺寸对比度最高。

## 4. 三端接入

### 4.1 Android（已完成）

| 路径 | 内容 |
| --- | --- |
| `res/mipmap-{mdpi..xxxhdpi}/ic_launcher.png`、`ic_launcher_round.png` | 方形/圆形启动器图标（48/72/96/144/192） |
| `res/drawable-{mdpi..xxxhdpi}/ic_launcher_foreground.png`、`ic_launcher_background.png` | 自适应图标图层：108dp 画布，前景图形占 62%（落在 72dp 安全区），背景满幅深蓝→青渐变 |
| `res/mipmap-anydpi-v26/ic_launcher.xml`、`ic_launcher_round.xml` | `<adaptive-icon>` 组合前后景 |
| `AndroidManifest.xml` | `android:icon="@mipmap/ic_launcher"`、`android:roundIcon="@mipmap/ic_launcher_round"` |

> 通知小图标：当前代码无通知（`grep setSmallIcon` 零命中），未落地资源；后续加通知请用 `brand/mono/emoreply-inverse-*.png`（系统会单色化，彩色图变灰块），已写入 `brand/README.md`。

### 4.2 iOS（资产预置，本机不可编译）

`ios-app` 是 SwiftPM 包，无 App target 与 `Assets.xcassets`，故无法接入 AppIcon（本环境不可落地）。已按 Xcode 规范预置：

`brand/ios/AppIcon.appiconset/` —— 15 张 PNG（20/29/40/58/60/76/80/87/120/152/167/180/1024）+ `Contents.json`（universal + ios-marketing）。
关键点：iOS 会再套圆角遮罩且 App Store 拒绝含 alpha 图标 → 脚本生成**满幅无 alpha 版本**（徽标放大到 100%，四角用同向渐变补齐，`icon-1024.png` 校验为 RGB、角点 alpha=255）。建 Xcode App 工程时把该目录拖入 `Assets.xcassets` 即可。

### 4.3 桌面端打包（已实打包验证）

- `package.json`：新增 `build` 配置（`appId=com.emoreply.desktop`、`productName=EmoReply`、`win.icon=assets/emoreply.ico`、`nsis.installerIcon/uninstallerIcon/installerHeaderIcon`、`mac.icon=assets/emoreply.icns`、`linux.icon=assets/emoreply-512.png`、target=nsis+portable、`files` 白名单含 `assets/**/*`），新增 `dist`/`dist:mac` 脚本，`devDependencies` 加 `electron-builder@^25.1.8`。
- `scripts/pkg-semver.js`（新增）：electron-builder 强制 version 为合法 semver，而本项目 patch 号是 `YYYYMMDD-NNN`（T01160 约定）→ 该脚本打包期临时改写为 `0.1.0-YYYYMMDD-NNN`，打包结束（无论成败）还原原文件，两条约定同时成立。`npm run dist` 即走这条链路。
- `assets/`：`emoreply-512.png`、`favicon.ico`；`index.html` 加 `<link rel="icon">`。
- 产物：`dist/EmoReply-0.1.0-20260927-004-x64.exe`（NSIS 82.7 MB）、`dist/...-portable.exe`（82.3 MB）、`dist/win-unpacked/EmoReply.exe`。

### 4.4 Web/PWA（顺带补齐）

`brand/favicon/`：`favicon.ico`（16/32/48）、`apple-touch-icon.png`（180）、`pwa-192.png`、`pwa-512.png`。

### 4.5 资产脚本修正（T01163 遗留缺陷）

`brand/_tools/build_assets.py`：

- **自适应图标前景画布错误**：原按启动器尺寸生成前景，作为 108dp 图层被放大顶出安全区 → 改为 108dp 画布（108/162/216/324/432），图形裁到自身 bbox 后按 62% 居中。
- **图形 mask 被外发光污染**：AI 出图外缘淡色外发光被误判成图形，前景占比仅 41% → 新增 `_erode()` 对 alpha 腐蚀 6px，只在徽标内部提取图形；修后占比 61–62%、反白版 bbox 干净。

## 5. 验证证据

1. **Android 编译**：`gradle assembleDebug --offline` → BUILD SUCCESSFUL（57s，35 tasks）。
2. **APK 图标声明**：`aapt2 dump badging` → `application-icon-*` 全密度指向 `res/mipmap-anydpi-v26/ic_launcher.xml`；`unzip -l` 确认全部图标资源打进包。
3. **自适应前景安全区**：前景占画布 61.1%（mdpi）/ 61.8%（xxxhdpi），中心偏移 < 72dp 安全区。
4. **iOS 图标集**：`Contents.json` 逐条校验 15 张图，尺寸与 `size×scale` 一致、全部 RGB 无 alpha，0 问题。
5. **桌面端实打包**：electron-builder 25.1.8 产出 NSIS + portable + win-unpacked，版本改写/还原均确认。
6. **exe 图标像素级验证**（自写 `tmp/extract_exe_icon.py` 走 PE 资源表 RT_ICON）：三者均内嵌 7 档图标（256/128/64/48/32/24/16）；抽出 256×256 与 `brand/png/emoreply-256.png` **逐像素平均差 = 0.0**（完全一致，非 Electron 默认图标）。
7. **矢量几何一致性**：`verify_svg.py` 解析 SVG 后光栅化，与位图母版 40×40 ASCII 构图比对——轮廓、气泡、爱心、星光、气泡尾逐行对齐。
8. **ICO/ICNS**：ICO 解析 7 条目 `[16,24,32,48,64,128,256]`；ICNS 含 `ic07/ic08/ic09/ic10`。
