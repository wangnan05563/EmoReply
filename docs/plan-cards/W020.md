## 关联需求（PRD/SRS 原文摘录，含验收准则）

### FR-3.1
- **FR-3.1【P0】** 基于可用上下文 + 关系 + 情绪 + 用户人设，调用云端 LLM 生成 2–3 个候选。
  - *上下文获取策略*（解决只读约束）：① 近期通知拼装伪历史（同一会话最近 N 条）；② 用户手动粘贴补全（FR-1.5）；③ 企业/授权场景取真实历史（二期）。**质量边界**：只读通知下上下文有限，回复以"礼貌得体、不编造事实"为下限，不承诺记忆长程对话。
  - *验收*：候选生成成功率 ≥ 95%（网络正常）；默认产出 2–3 条；不出现编造对方未提及事实。

### FR-3.2
- **FR-3.2【P1】** 支持语气风格切换：正式 / 亲切 / 简短 / 幽默。
  - *验收*：四种风格可切换且风格区分可被人工辨识（抽样 ≥ 90%）。

### FR-3.3
- **FR-3.3【P1】** 附一句"为什么这样回"（解释情商点，提升可信度）。
  - *验收*：≥ 90% 候选附带可理解的解释句。

### FR-3.4
- **FR-3.4【P2】** 支持用户微调（改写、补充事实、指定长度）。
  - *验收*：微调后 ≤ 2 次交互内重新生成。

## 设计依据（HLD）

- 职责：系统提示+画像+上下文 → LLM → 多候选 + 风格
- 模块关联需求：FR-3.1/3.2/3.3/3.4
