## 二、优化点（按优先级排序）

### 高优先级

**P1 · 一键清除无二次确认（数据安全事故级）**
- 问题：`MainActivity.kt:137` 点击后**立即**执行 `FeedbackStore/GeneratorSettings/PersonaStore/KnowledgeBase/TemplateStore/ReplyStore` 全部清空，含加密 API Key 与全部知识库，无任何确认。
- 建议：`MaterialAlertDialog` 二次确认（标题红字"清除全部本地数据"、正文列明将丢失的内容、"清除"按钮红色 + 需输入"清除"或长按 2s 触发二选一）。
- 收益：消除误触导致不可逆数据丢失的唯一途径；正式版上线前必须修复。

**P2 · 单页 4.5 屏平铺、无分组导航**
- 问题：10 个区块线性堆叠，高频项（风格/人设/知识库）压在第 3–4 屏，低频项（版本更新）反而占据第 2 屏。
- 建议：改「**状态卡 + 分组卡片 + 危险区独立**」三段式（详见第三节布局对比）；不引入底部导航，保持单 Activity 结构，改动可控。
- 收益：高频项首屏可达；信息层级从"滚动距离"升级为"卡片边界"。

**P3 · 输入框无持久标签**
- 问题：仅靠 hint，输入后字段语义消失（截图 1 已证实）；表单类设置项 7 个 EditText 全部如此。
- 建议：全部替换 `TextInputLayout`（Material）悬浮 label + 错误内联校验（URL 格式、Key 非空）。
- 收益：填完仍知所填；错误即时可见，减少"保存了但没生效"类困惑。

**P4 · 授权引导长期占据顶部黄金位**
- 问题：①②③三按钮在授权完成后仍固定于首屏，日常使用毫无价值（截图 1：已授权状态仍全宽展示）。
- 建议：改造为「连接状态卡」——未完成项展开显示引导按钮，全部就绪折叠为一行绿底"✓ 已就绪"，点击展开详情；"最近捕获"并入此卡。
- 收益：首屏让位给高频设置项；状态一览从 3 行文本变 1 张语义色卡。

### 中优先级

**P5 · 无视觉主题体系（POC 观感）**
- 问题：原生灰按钮 + 纯文本分区，与正式版定位不符。
- 建议：升级 Material 3 主题；区块用 `MaterialCardView`（圆角 12dp、1dp 描边、8/16dp 间距节奏）；主操作用 FilledButton，次操作 OutlinedButton。
- 收益：视觉质量达正式版标准；卡片边界天然承担 P2 的分组职能。

**P6 · API Key 无可见性切换、无连通性测试**
- 问题：`inputType="textPassword"` 且无切换，填错只能盲改；本会话 T01081/T01082 调试中即发生 Key 抄录错误且难定位。
- 建议：`TextInputLayout.endIcon=PasswordToggle`；新增"测试连接"按钮（发起一次最小补全请求，回显模型名+耗时）。
- 收益：Key 类故障可自助排查（本次排查实测痛点）。

**P7 · 保存反馈过弱**
- 问题：保存结果以 12sp 状态文本呈现，无成功/失败色彩；用户易忽略。
- 建议：统一 `Snackbar` 成功/失败反馈；状态行保留作详细回显。
- 收益：操作闭环明确，降低重复点击保存。

**P8 · 「回复风格/人设/知识库」生成质量项应聚合**
- 问题：三者分散于第 3–4 屏且中间夹着版本更新。
- 建议：聚合为"生成质量"分组（风格→人设与关系→知识库），紧随状态卡之后。
- 收益：心智模型统一——"影响回复质量的都在这一组"。

### 低优先级

**P9 · 版本更新区收纳**
- 问题：极低频运维项占据第 2 屏整屏。
- 建议：折叠为"关于与更新"卡片（默认收起，显示当前版本号；点开才见检查更新）。
- 收益：回收约 1 屏空间。

**P10 · 深色模式**
- 建议：Material 3 `Theme.Material3.DayNight` 直接跟随系统，成本近乎为零（P5 顺带完成）。

**P11 · 设置搜索**
- 建议：正式版设置项稳定在 15+ 后再评估引入，当前不必要。

## 三、布局对比说明

**现状（线性 10 区块，4.5 屏）：**

```
[标题+3行状态文本]
[①通知权] [②启用输入法] [③切换输入法]   ← 首装后仍占首屏
[最近捕获…]
—— 云端生成设置 ——  CheckBox/URL/模型/Key/保存
—— 版本更新 ——      URL/检查/更新/进度    ← 低频占第2屏
—— 回复风格 ——      Spinner              ← 高频压到第3屏
—— 反馈统计 ——      纯文本
—— 人设与关系 ——    6 控件 2 保存钮
—— RAG知识库 ——     5 控件
[一键清除全部本地数据]                      ← 危险操作无隔离
```

**优化后（状态卡 + 分组卡片 + 危险区，首屏 1.5 屏内）：**

```
┌─ 连接状态卡（语义色：绿=就绪 / 黄=部分缺失）────────┐
│ ✓ 通知监听 · ✓ 输入法启用 · ✗ 非默认（点开引导）   │
│ 最近捕获：…（就绪时折叠为一行）                    │
└───────────────────────────────────────────────┘
┌─ 云端生成 卡片 ────────────────────────────────────┐
│ 启用开关｜Base URL▾label｜模型▾label              │
│ API Key [👁切换] [测试连接]  保存（Filled）        │
└───────────────────────────────────────────────┘
┌─ 生成质量 卡片（风格 → 人设与关系 → 知识库）────────┐
│ 回复风格 Spinner ｜ 采纳率 100%（5/0）             │
│ 我/禁语/联系人/关系 ｜ 知识库条目（0 条）           │
└───────────────────────────────────────────────┘
┌─ 关于与更新 卡片（默认折叠）────────────────────────┐
│ v1.0.x · 展开显示检查更新/清单 URL                 │
└───────────────────────────────────────────────┘
  ⚠ 危险区（独立描红卡片 + 二次确认对话框）
  [ 清除全部本地数据 ]
```

对比要点：①首屏从"引导按钮"变为"状态语义卡"；②高频生成项从第 3–4 屏提前到首屏；③低频运维折叠；④危险操作从"最后一个普通按钮"变为"视觉隔离 + 确认门槛"。单 Activity/单页结构不变，全部为布局层改造 + 少量对话框代码，不触碰业务链路。
