# EmoReply PC 优化需求 PRD（T01360）

## 1. 背景与目标

EmoReply PC（Electron 桌面端）目前处于 POC 形态：悬浮窗（frameless + alwaysOnTop）+ 剪贴板读/写交付 + OpenAI 兼容 LLM 生成 + 本地模板降级 + 知识库（kb）基础 CRUD。移动端 Android 已沉淀大量成熟能力（读屏 OCR、侧别上下文、候选清洗、人设库 RAG 等），PC 端尚未同步。

本 PRD 基于两类输入整理 PC 端迭代需求：
1. **GitHub 同类产品调研**（10 款：openai-translator、pot-app、Grammarly Desktop、Chatbox、uTools AI快闪、PopClip/SnipDo、wechat-ai-assistant、ReplyWise-Local、chatgpt-on-wechat、Chat-Style-Bot）；
2. **移动端已有功能盘点**（Android 端能力向 PC 端移植评估）。

目标：形成可排期的 PC 端优化需求清单，覆盖客户体验、功能扩展、UI、主题四个维度。

## 5. 约束与验收口径

- **零留存延续**：历史记录默认不存（SRS 口径），开启即须加密。
- **密钥不出设备**：API Key 本机加密存储（沿用现行方案）。
- **架构约定**：新能力先在 m1-poc（Python）验证再镜像端侧；PC 端 JS 与 kt/py 保持同构（尤其候选清洗）。
- **验收**：每条 FR 以「构建全链通过 + 启动冒烟 + 核心路径手动验证」为 done 门槛；UI 类需真机（桌面）实测截图佐证。
- 后续排期建议按 P0 → P1 → P2 拆里程碑回写任务系统（沿用 Gen-PatchVersion 构建链验证）。
