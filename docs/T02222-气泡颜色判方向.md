# T02222 变更说明：基于气泡颜色的微信读屏方向判定

> 状态：代码完成、离线回归与真机**历史截图**数据验证通过；真机安装回测待设备联机（见文末）。
> 事实源：`m1-poc/emoreply/bubble_side.py`（14 条回归用例）；Android 同构实现：
> `capture/BubbleSideJudge.kt` + `EmoReplyReaderService.judgeSides`；调用侧提示：
> `EmoReplyImeService.applyReadResult`。

## 1. 为什么改

原判侧只用「OCR 行框左缘 ≥ 屏宽 × 0.3125 → 我说」（T01143/T01150）。行框左缘会随
字号缩放、折行合并取最小左缘、头像/图标字形粘连而漂移，真机已出现「对方长气泡判成我」
「我方发言判成对方」两类反馈。气泡底色是微信的平台强特征，与坐标无关，故作为主判据。

## 2. 判定链路

```
截图(cropped bitmap)
  └─ 逐行：OCR 行框 [left,right,top,bottom]
       ├─ ① 页面基线：左缘/右缘各取一条（聊天背景图可能带渐变）
       │     取样点 (x=2,4) 与 (x=w-3,w-5)，y = 行中线 ±40px，取众数
       ├─ ② 取样：文本框四周内边距带 30 点
       │     水平：left-{8,20,32}、right+{8,20,32} × 行高 25%/50%/75%
       │     垂直：top-{8,16}、bottom+{8,16} × 行宽 30%/50%/70%
       ├─ ③ 单点三分类 classifySample（顺序即优先级）
       │     与任一页底基线同色(通道差≤4) ────────→ 作废(页底)
       │     g-max(r,b)≥18 且 g≥90 ─────────────→ 我说(绿)   ★锚点 #95EC69/#A9EA7C
       │     彩色(通道跨度>14) ──────────────────→ 作废(图片/表情/头像)
       │     中性(跨度≤14)且比页底亮一档 ────────→ 对方说(白) ★锚点 #FFFFFF/#F2F2F2
       │     其余(字形/描边/撞色) ───────────────→ 作废
       ├─ ④ 投票：绿≥2 且 ≥白 → 我说；白≥2 且 >绿 → 对方；否则颜色不可用
       └─ ⑤ 回退：颜色不可用 / 非微信 / 超预算 → isMine(left, sw) 位置判定，记入「存疑」
```

「非微信」判定：`svc.windows` 中存在 `com.tencent.mm` 的应用窗时才启用颜色规则；
钉钉/QQ/短信气泡色各异，沿用位置判定（不取样、零开销）。

## 3. 阈值参数（改动须同步 py 与 kt 两侧）

| 常量 | 值 | 含义与依据 |
| --- | --- | --- |
| `GREEN_DELTA` | 18 | `g - max(r,b)` 下限；#95EC69 实测差 87、#A9EA7C 差 65，深色绿 #1AAB39 差 114 |
| `GREEN_MIN_G` | 90 | 绿通道绝对亮度下限，排掉黑字边缘的暗色噪点 |
| `NEUTRAL_MAX_SPAN` | 14 | `max-min` 上限，近中性（白/灰）判定；照片/壁纸多超过此值 |
| `PAGE_EPS` | 4 | 与页底基线的通道级差上限：≤4 视为页底本身，样本作废 |
| `LIGHT_MIN_CHANNEL` | 225 | 浅色主题白气泡的最低通道值（#F2F2F2=242、#E0E0E0=224 排除） |
| `LIGHT_STEP_UP` | 5 | 白气泡须比「更亮那侧页底」还亮 ≥5 档：#F2F2F2 vs #EDEDED 差 5 是极值场景 |
| `LIGHT_PAGE_LUM` | 80 | 页底明度低于此值 → 判为深色主题，走深色分支 |
| `DARK_STEP_UP` / `DARK_STEP_CAP` | 12 / 110 | 深色：气泡比页底亮 12~110 档（#2C2C2C on #111111 差 27；近白字形差 238 被排除） |
| `DARK_MAX_LUM` | 210 | 深色气泡绝对明度上限，同样为排掉白色字形 |
| `MIN_VOTES` | 2 | 决定性样本下限（单点不定，防偶发撞色） |
| `SIDE_TOTAL_BUDGET_MS` | 300 | 整屏颜色判侧累计预算，超出后剩余行全部走位置回退 |
| `SIDE_BUDGET_MS` | 50 | 单行耗时红线（任务验收指标），超限打 warning 日志 |

实测性能（合成 1440 宽屏、60 行）：单行 ~0.1-0.3ms，整屏 < 30ms；真机路径每行只读
30 次 `Bitmap.getPixel`。

## 4. 回退逻辑与不确定性提示

- **回退触发**：非微信窗口 / 深色主题读不出 / 取样全部作废（图片消息、群聊昵称行）/
  整屏预算超限。回退到 `isMine(left, screenWidth)`（左缘 ≥ 屏宽×0.3125 → 我说）。
- **提示**：读屏完成后统计方向来源（`EmoReplyReaderService.sideStats()`），IME 状态行显示
  「方向按位置判断（可能有误）」（全部回退）或「其中 N 条方向按位置判断」（部分回退）。
  节点树路径没有截图像素，方向全部来自位置判定，同样计入「存疑」。

## 6. 已知限制

1. 白气泡与页底档差 <5（如 #F2F2F2 气泡 + 近白页底）时颜色不判定 → 位置回退并提示。
2. 照片背景图含接近纯白的大块区域时，该处取样可能产生零星白票，靠 ≥2 票 + 多数决兜住；
   图片消息的图内文字已被 T01334 区域/簇过滤先行剔除。
3. 自定义彩色主题（非绿非白气泡）→ 颜色不可用 → 位置回退（符合任务「非标准主题回退」要求）。
4. 节点树路径（非微信常用）无像素取样，仍是纯位置判定（不计入颜色收益）。
