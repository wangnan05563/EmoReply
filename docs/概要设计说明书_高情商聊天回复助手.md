## 1. 文档概述

### 1.1 编写目的
定义 EmoReply 的系统总体架构、模块划分、数据设计、接口设计与非功能性设计，作为详细设计与开发实现的依据，并支撑 SRS 中 FR/NFR 的可追溯落地。

### 1.2 适用范围
覆盖：Android 端（主交付）、桌面端（Windows/macOS，悬浮窗+剪贴板先行）、云端生成服务。iOS 为实验性/二期（独立 App+复制），不在本概要设计的主体范围。

### 1.3 术语
- **IME**：输入法扩展（Android InputMethodService / Windows TSF / macOS IMK）。
- **捕获层**：通过系统通知监听（只读）获取消息的服务。
- **交付层**：输入法候选条 / 悬浮窗，负责把候选回复呈现并注入或复制。
- **AI 条**：输入法候选条上方独立的候选回复展示区，不与拼音候选混排。

### 1.4 参考文献
SRS v1.0；Android `NotificationListenerService` / `InputMethodService` 文档；Windows TSF / macOS IMK 文档；《个人信息保护法》《数据安全法》。

## 2. 系统总体架构

### 2.1 架构图（逻辑 + 部署视图）

```
┌──────────────────────── 端侧（设备内） ────────────────────────┐
│  [捕获层]                        [交付层]                      │
│  通知监听服务(只读)              自定义 IME (Android)           │
│   ├ 通知载荷解析                  ├ 普通拼音键盘（复用内核）      │
│   ├ 去重/过滤/指向判定            ├ AI 条（候选 2–3 条）         │
│   └ 上下文拼装(伪历史)            └ 点选 → 注入输入框 / 复制     │
│         │                              ▲                       │
│         └─────► [本地上下文存储(加密)] ─┘                       │
│                        │ 设备内安全通道（不出设备）              │
└────────────────────────┼───────────────────────────────────────┘
                         │ HTTPS / TLS（仅正文生成时上云）
                         ▼
┌──────────────────── 云端（生成服务） ─────────────────────────┐
│  [API 网关] → [会话编排服务]                                   │
│                 ├ 画像注入（角色/风格）                        │
│                 ├ 安全护栏（云端层：敏感词/诈骗/承诺）           │
│                 ├ LLM Provider 适配（多模型可切换）             │
│                 └ 候选生成（2–3 条 + 风格标签）                 │
│  [可选] RAG 检索服务（人设库/话术模板/平台礼仪）— 待决策         │
│  [日志/埋点] 采纳·修改·忽略（脱敏，不含正文）                   │
└───────────────────────────────────────────────────────────────┘
```

### 2.2 技术栈

| 层 | 选型 | 说明 |
|----|------|------|
| Android 端 | Kotlin + 系统 `NotificationListenerService` + `InputMethodService` | IME 内核**建议复用开源 IME（如 FlorisBoard / 拼音 SDK）裁剪**，不自研全键盘（待决策，见 §8） |
| 桌面端 | Electron 或 TSF/IMK 扩展 + 悬浮窗 | 首期悬浮窗+剪贴板，完整 IME 二期 |
| 云端 | Node/Python 服务 + LLM Provider 适配层 | 多模型可切换，BYOK 预留 |
| 向量/缓存 | 本地 SQLite（加密）；可选 pgvector/chromadb（RAG，待决策） | 元数据本地优先 |
| 传输 | TLS 1.2+；端云仅传生成必要正文 | 见 §7.2 |

### 2.3 分层结构
1. **接入层**：通知捕获 Adapter（插件式，可插拔可摘除）。
2. **理解层**：意图/情感/紧急度/需回复判定（规则 + 模型混合）。
3. **生成层**：prompt 编排 + LLM + 双层护栏。
4. **交付层**：IME AI 条 / 悬浮窗 / 复制。
5. **支撑层**：加密存储、埋点、配置与人设同步、降级开关。

## 4. 数据库设计（概要）

本地加密存储（设备级密钥），核心实体：

| 实体 | 关键字段 | 说明 |
|------|----------|------|
| Message（消息元数据） | id, app, sender, sessionKey, time, type, isDirected | **不含长期正文留存** |
| ContextSnippet（上下文片段） | sessionKey, seq, text, ts | 伪历史；加密短时缓存 ≤7 天（可配置） |
| ContactProfile（联系人画像） | contactKey, relation, 人称 | 本地加密；未标注默认「陌生」 |
| UserPersona（用户人设） | selfName, 口头禅, 禁语, defaultStyle, version | 多端同步，冲突「最后写入优先+版本号」 |
| FeedbackLog（反馈） | ts, action(采纳/修改/忽略), style | 脱敏，不含正文；上云须授权 |
| GenCache（生成缓存） | hash, candidates, ts | 弱网/离线模板兜底 |

**E-R 要点**：Message → sessionKey → ContextSnippet（1:N）；ContactProfile 与 UserPersona 独立；FeedbackLog 仅引用 style 不引用正文。

## 5. 接口设计（概要）

### 5.1 端 ↔ 云
- `POST /v1/reply/generate`
  - 入参：`{ sessionKey, snippets[], persona{role,style}, contactRelation, intent, topK }`（正文仅生成时上云）
  - 出参：`{ candidates:[{text, style, reason}], degraded:boolean }`
  - 非功能：流式可选；P95 < 3s（含网络）
- `GET /v1/models` —— 拉取当前 Provider 可用模型列表（**C2/C15**：动态拉取，列表需可滚动不截断，供多模型切换 / BYOK 使用）
- `POST /v1/feedback`（须授权、脱敏）
- `POST /v1/safety/check`（可选，本地护栏兜底时调用）

### 5.2 端内（模块间）
- 捕获层 → 理解层：`NotificationCaptured(payload)`（本地广播/事件总线）
- 理解层 → 生成层：`DirectiveContext(snippets, intent, relation)`
- 生成层 → 交付层：`CandidatesReady(candidates)`
- 交付层 → 反馈：`FeedbackEvent(action)`

### 5.3 外部依赖
- LLM Provider API（可切换，BYOK 预留）
- 系统能力：通知监听、输入法框架、剪贴板

## 6. 关键流程与算法

### 6.1 主流程（一次「AI 帮写」）
1. 通知到达 → M1 解析载荷 → 若空载荷走 FR-1.5 兜底（提示粘贴/泛化建议并标注）。
2. M2 去重 + 指向判定（首期：私聊/@/引用硬规则）。
3. M3 拼装上下文（同会话近期 N 条伪历史）。
4. M4 意图/情感/紧急度/需回复判定。
5. M5 编排 prompt（系统约束 + 人设 + 关系 + 上下文）→ LLM → 2–3 候选。
6. M6 双层护栏过滤。
7. M7 AI 条呈现 → 用户点选 → 注入输入框/复制。
8. **用户手动发送**（产品不代发）；M8 记录反馈。

### 6.2 降级流程
- 弱网/超时（默认 3s）→ M9 本地模板 + 标注「离线草稿」→ 恢复后自动切回云端。
- 捕获层被摘除（政策/授权）→ 降级为纯手动粘贴（独立 App/悬浮窗），M5–M7 仍可用。
- 纯本地模式开关 → 关闭上云，仅本地模板（质量降级，UI 明示）。

### 6.3 关键算法要点
- **指向判定（首期）**：`私聊 = true`；`群聊 = @我 || 引用我`；其余不判定为需回复（FR-1.6 纯语义列二期）。
- **上下文拼装（含 token 预算，C16）**：按 sessionKey 取最近 N 条（默认 6），按时间升序；**先估算 token，超模型上限时按策略截断（保留最近 + 系统约束），不得硬失败**（参照 compare T00181：输入 195504 > 上限 131072 直接报错）；缺失不臆造。
- **语义保真校验（C10）**：风格压缩/改写后需校验未丢失原意（参照 mtask T00546/T00524）。
- **护栏**：规则（敏感词/OTP/钱财索取）优先于模型，命中即拒绝并给风险提示，不生成迎合内容。

## 7. 非功能性设计

### 7.1 性能
- 捕获到占位提示 <1s；候选就绪 P95 <3s（云端含网络）；IME 注入无明显卡顿。
- 优化：打字时并行预检索；候选流式渲染；高频话术本地缓存。

### 7.2 安全与隐私（重点）
- 传输 TLS；端侧缓存设备级密钥加密；端云仅传生成所需正文，短期缓存 ≤7 天（可配置），不长期留存。
- **按键流纪律**：IME 不对外传输、不上传、不外存按键流；按键仅本地用于输入功能（须过安全审计）。
- 最小权限；一键清除本地数据；可关闭云同步/云生成。

### 7.3 可靠性与降级
- 捕获层可插拔（硬约束）；LLM 多 Provider 可切换 + 超时降级；离线模板兜底。

### 7.4 可扩展性
- 新增 IM 平台 = 新增捕获 Adapter（不改核心与交付层）；新增 LLM = Provider 适配。

### 7.5 监控与日志
- 埋点：捕获成功率、生成成功率/时延、采纳率/修改率/忽略率、护栏命中率、降级触发次数。
- 日志脱敏（不含消息正文）；本地留存，上云须授权。

## 8. 风险评估与应对

| 风险 | 等级 | 设计层面应对 |
|------|------|--------------|
| Android 全键盘 IME 自研成本 | 🔴 高 | **内核复用开源 IME 裁剪**（待拍板——直接决定 M1/M2 工时）；备选：悬浮窗+剪贴板为主交付面 |
| iOS 键盘扩展能力受限 | 🟠 中高 | 首期仅实验性/二期；独立 App+复制降级 |
| 通知上下文贫乏致「高情商」质量受限 | 🔴 高 | 质量定位务实化为「得体安全不冷场」；「显示详情」设为验收强前置；Phase2 企业授权取真实历史 |
| 平台政策收紧 | 🟠 中高 | 捕获层可插拔 + 一键降级纯手动粘贴（架构硬约束） |
| 隐私泄露 | 🟠 中 | 最小收集、加密、用完即焚、纯本地模式开关、按键流审计 |
| 云端成本/网络 | 🟡 低中 | 订阅额度 + 缓存 + 弱网降级 |
| RAG 缺失致差异化不足 | 🟡 低中 | 待决策：补 RAG（人设库/话术/礼仪）或定位改名「得体回复助手」 |
