## 1. App 设置页重新布局与优化（T01083）

对象：android-app 设置页（`activity_main.xml` + `MainActivity.kt`）。依据：代码逐行梳理 + 真机截图四张。

### 1.1 现状

单页 ScrollView 平铺 10 个区块（约 4.5 屏）：标题状态、授权引导（3 按钮）、最近捕获、云端生成设置、版本更新、回复风格、反馈统计、人设与关系、RAG 知识库、一键清除。问题：系统原生灰按钮无主题、无卡片；输入框填值后 hint 消失；状态信息无成功/失败语义色。

### 1.2 优化点（按优先级）

| 优先级 | 项 | 问题与建议 |
| --- | --- | --- |
| P1 高 | 一键清除无二次确认 | 立即清空全部本地数据（含加密 Key/知识库）→ `MaterialAlertDialog` 二次确认（红字标题、列明丢失内容、红色按钮需输入"清除"或长按 2s）。上线前必须修复 |
| P2 高 | 单页 4.5 屏无分组 | 改「状态卡 + 分组卡片 + 危险区独立」三段式，不引入底部导航，保持单 Activity |
| P3 高 | 输入框无持久标签 | 7 个 EditText 全部换 `TextInputLayout` 悬浮 label + 错误内联校验 |
| P4 高 | 授权引导长期占首屏 | 改「连接状态卡」：未就绪展开引导，就绪折叠为一行绿底"✓ 已就绪"，"最近捕获"并入 |
| P5 中 | 无视觉主题体系 | 升级 Material 3 主题；区块用 `MaterialCardView`（圆角 12dp、1dp 描边）；主操 FilledButton、次 OutlinedButton |
| P6 中 | API Key 无可见性切换/连通测试 | `TextInputLayout` PasswordToggle + "测试连接"按钮（最小补全请求回显模型名+耗时） |
| P7 中 | 保存反馈过弱 | 统一 `Snackbar` 成功/失败反馈 |
| P8 中 | 质量项分散 | 聚合为"生成质量"分组（风格→人设与关系→知识库） |
| P9 低 | 版本更新占第 2 屏 | 折叠为"关于与更新"卡片（默认收起，显示版本号） |
| P10 低 | 深色模式 | Material 3 `DayNight` 跟随系统（P5 顺带完成） |
| P11 低 | 设置搜索 | 项稳定 15+ 后再评估，当前不必要 |

### 1.3 布局对比

优化后结构（首屏 1.5 屏内）：`连接状态卡`（语义色绿=就绪/黄=部分缺失，含最近捕获）→ `云端生成卡片`（开关/URL/模型/Key[👁][测试连接]）→ `生成质量卡片`（风格/人设关系/知识库）→ `关于与更新卡片`（默认折叠）→ `⚠ 危险区`（独立描红 + 二次确认）。

落地清单（组件级）：P1 AlertDialog；P2/P5/P8 Material3 + 5 张分组卡片；P3 6 处 EditText→TextInputLayout；P4 状态卡折叠/展开；P6 PasswordToggle + 测试连接；P7 Snackbar；P9 关于折叠卡。工作量：P1 半天；P2+P5+P3+P9 合计 2–3 天；P4/P6/P7 各半天。建议顺序 P1 → (P2+P5+P3+P9) → P8 → P4 → P6 → P7。

## 2. 多平台消息接入扩展评估（T01097）

结论先行：**四平台官方 API 均无法满足「用户个人消息只读接入」——官方能力只覆盖「与机器人相关的消息」，全量消息读取均为企业级付费/管控能力，个人开发者不可达。通用合规路径仍为系统通知监听。**

| 平台 | 个人可达路径 | 收到什么 | 全量读取 | 判定 |
| --- | --- | --- | --- | --- |
| 企业微信 | 无 | — | 企业付费专区 | ❌ 不可行 |
| 飞书 | 自建应用机器人 | 单聊 bot / 群 @bot | 需企业管理员授权 | ⚠️ 仅 bot 模式 |
| QQ | 开放平台机器人 | 单聊 bot / 群 @bot | 私域权限需企业 | ⚠️ 仅 bot 模式（禁 URL、被动消息窗口） |
| 钉钉 | 企业机器人 | 单聊 bot / 群 @bot | 客联企业场景 | ⚠️ 仅 bot 模式 |
| **系统通知监听**（现状） | 用户授权即可 | **用户本人全部通知** | —（只读） | ✅ 唯一通用路径 |

建议：
1. 多平台个人消息接入维持现状（Android 系统通知监听，SRS FR-1.1 设计正确）。
2. 可做的延伸（另立观察单，不排期）：飞书/QQ/钉钉机器人模式（用户转发消息给 bot 求建议，飞书个人版成本最低）；邮件接入（IMAP/OAuth 是用户自己账号，语义匹配，是二期唯一路径匹配平台）。
3. 明确不做：任何 UI 自动化/无障碍读取聊天内容（违反 SRS 合规红线 2.4）。

## 3. 读屏功能与候选生成优化（T01343）

关联代码：`m1-poc/emoreply/preprocess.py`、`EmoReplyReaderService.kt`、`EmoReplyImeService.kt`、`UxSettings.kt`。四项核心修复已落地（m1-poc + Android）。

### 3.1 根因

1. **方向错位**：侧别阈值 `SELF_SIDE_LEFT_PX=450px` 为绝对像素，隐含屏宽=1440 假设；1080/720 宽设备大量误判。
2. **范围固定一屏**：`extraScreens=1` 硬编码，长讨论无法扩大。
3. **上下文过多混杂旧话题**：`splitDialogueTurns` 把全部历史按原序送 prompt（无上限）。
4. **时间戳未利用**：纯时间行被当噪声丢弃，恰是话题边界信号。

### 3.2 方案（已实施 ✅）

- **侧别改相对屏宽比例**：`left >= screenWidth × 0.3125`（`450f/1440f`），节点树与 OCR 路径统一传 `screenWidthPx()`，未连接回落 1440。
- **读屏范围可配置**：`UxSettings.read_screens`（1–3 屏，默认 1）；设置页滑杆；`captureMultiScreen(extraScreens = readScreens - 1)`；每多一屏约 +600ms 上滑 + 0.5–0.75s OCR。
- **时间分段 + 条数上限（双保险）**：时间/日期行转 `时间：xxx` 标记行，遇标记开启新话题段、此前内容整段丢弃；`history` 超 `HISTORY_LIMIT=12` 条只保留最近 12 条；`history_limit=None` 可关闭；无标记时行为同旧版。

### 3.3 后续可选（⏳ 未实施）

话题分段识别（侧别切换频次/LCS）、时间窗口截断（OCR 无日期不可靠，暂不做）、候选相关性排序（属 sanitize/rank 层）。

### 3.4 待确认

- 0.3125 跨设备有效性（需非 1440 宽真机）；时间标记行误保留风险（正文恰为纯时刻概率低）；history 上限 12 是否合适（偏小可放 16）；读屏范围默认值维持 1 屏。
- 验证：m1-poc pytest **306 passed**（新增 `test_t01343_context.py` 15 例）；Android 构建通过。

## 4. 钉钉「AI 灵动回复」分析与借鉴（T01345）

结论先行：**钉钉做对的是"用多样性 + 关系感知对冲单条生成不确定性，并把最后一道质量关留给人类"——是产品设计问题，4 条可低成本迁移。**

### 4.1 钉钉六机制

关系感知决定语气分布 / 多样性覆盖而非单一最优（一次 4–6 条跨风格）/ 人机分工（AI 只出草稿）/ 情境分类层 / 个性化反馈闭环 / 灰度 + 数据驱动准入。平台原则：质量为王（不稳定即零）、大量工程少量算法、快慢思考结合、全链路可干预、自动评估闭环。

### 4.2 与本项目对照（差距）

| 钉钉机制 | 本项目现状 | 差距 |
| --- | --- | --- |
| 关系感知决定语气 | `PersonaStore.relation` 已有，但 `UxSettings.tone` 是全局单值滑杆，不随对端关系自动变 | ⚠️ 有数据没用上 |
| 一次多风格 4–6 条 | 候选条数不固定，`STYLES`+`toneHint` 单档位约束 → 多条基本同语气 | ⚠️ 缺跨风格并行 |
| 二次编辑后发送 | 候选注入输入框可编辑再发（T01127 起） | ✅ 已对齐 |
| 棘手情境识别 | `Guardrail.screenIncoming/screenCandidate` 敏感信息拦截 | ✅ 我们更硬 |
| 个性化反馈闭环 | `FeedbackStore` 只统计不反作用于生成 | ⚠️ 断环 |
| 快慢思考 | IME 延迟极敏感 | ❌ 不应照搬 |

差异化优势（应加强）：跨 App 读屏上下文、候选理由列（rationale）、输入侧敏感护栏、零留存 + 端侧可选。

### 4.3 可借鉴优化项（按 ROI）

- **P0-1 关系感知 → 语气默认档位**：`UxSettings.tone` 增 AUTO（`-1`），按 `PersonaStore.relation` 映射默认 tone（上级/客户≈30–40，同事≈55–60，好友/家人≈70–80），手动可覆盖并记忆。落点：`EmoReplyImeService.runManualPipeline` 查 relation 映射。
- **P0-2 多风格并行生成**：tone 展开 2–3 档各出 1–2 条；优先"单请求多语气"（不增 RTT），实测延迟可接受才考虑并发。
- **P1-1 棘手情境标签**：`core/Situation.kt`（正则+关键词，可单测）识别过度承诺/蹭车/借钱/甩锅，命中注入提示词约束。
- **P1-2 采纳率闭环接回生成**：`FeedbackStore.adoptionRate()` 按 `relation×tone×style` 统计，长期 <30% 自动下调默认 tone 一档或路由到 `TemplateStore` 模板（推理侧路由，等价替代训练回流）。
- **P2 灰度数据准入**：新能力默认 off，达标签转正。

### 4.4 不建议照搬

DingAutoEvaluator 训练回流（无训练闭环，用 P1-2 取代）/ 慢思考（IME 延迟第一约束，应保快用多候选对冲）/ 委托权限体系（不适用）/ 固定出 4–6 条（应动态）。

## 5. 基于气泡颜色的微信读屏方向判定（T02222）

事实源：`m1-poc/emoreply/bubble_side.py`（14 条回归用例）；Android 同构 `capture/BubbleSideJudge.kt` + `EmoReplyReaderService.judgeSides`。

### 5.1 为什么改

原判侧只用 OCR 行框左缘 ≥ 屏宽×0.3125。左缘会随字号缩放、折行合并、头像粘连漂移，真机已出现两类误判。气泡底色是微信平台强特征，与坐标无关，故作为主判据。

### 5.2 判定链路

```
截图 → 逐行 OCR 行框
  ├─ ① 页面基线：左右缘各取一条，取样点众数
  ├─ ② 取样：文本框四周内边距带 30 点
  ├─ ③ 单点三分类 classifySample（顺序=优先级）
  │     与页底基线同色(差≤4) → 作废(页底)
  │     g-max(r,b)≥18 且 g≥90 → 我说(绿) 锚点 #95EC69/#A9EA7C
  │     彩色(跨度>14) → 作废(图片/表情/头像)
  │     中性(跨度≤14)且比页底亮一档 → 对方说(白) 锚点 #FFFFFF/#F2F2F2
  │     其余 → 作废
  ├─ ④ 投票：绿≥2 且 ≥白 → 我说；白≥2 且 >绿 → 对方；否则颜色不可用
  └─ ⑤ 回退：颜色不可用/非微信/超预算 → isMine(left,sw) 位置判定，记「存疑」
```
「非微信」：`svc.windows` 存在 `com.tencent.mm` 才启用颜色规则；钉钉/QQ/短信沿用位置判定。

### 5.3 阈值参数（改动须同步 py 与 kt 两侧）

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `GREEN_DELTA` | 18 | `g-max(r,b)` 下限 |
| `GREEN_MIN_G` | 90 | 绿通道绝对亮度下限 |
| `NEUTRAL_MAX_SPAN` | 14 | 近中性（白/灰）判定上限 |
| `PAGE_EPS` | 4 | 与页底基线通道级差上限 |
| `LIGHT_MIN_CHANNEL` | 225 | 浅色主题白气泡最低通道值 |
| `LIGHT_STEP_UP` | 5 | 白气泡须比页底亮 ≥5 档 |
| `LIGHT_PAGE_LUM` | 80 | 页底明度低于此 → 深色分支 |
| `DARK_STEP_UP` / `DARK_STEP_CAP` | 12 / 110 | 深色气泡比页底亮 12~110 档 |
| `DARK_MAX_LUM` | 210 | 深色气泡绝对明度上限 |
| `MIN_VOTES` | 2 | 决定性样本下限 |
| `SIDE_TOTAL_BUDGET_MS` | 300 | 整屏颜色判侧累计预算 |
| `SIDE_BUDGET_MS` | 50 | 单行耗时红线（warning 日志） |

实测性能：合成 1440 宽屏 60 行，单行 ~0.1–0.3ms，整屏 <30ms；真机每行只读 30 次 `Bitmap.getPixel`。

### 5.4 回退与限制

- 回退触发：非微信窗口 / 深色主题读不出 / 取样全部作废 / 整屏预算超限 → `isMine(left, screenWidth)`；IME 状态行提示「方向按位置判断（可能有误）」。
- 限制：白气泡与页底档差 <5 时颜色不判定；照片背景图零星白票靠 ≥2 票兜住；自定义彩色主题 → 位置回退；节点树路径无像素取样仍纯位置判定。
- 回滚：删除 `judgeSides` 调用并恢复 `isMine` 前缀写法即可；`BubbleSideJudge.kt` 与 py 模块可整体移除，无持久化数据。
- 验证：py 回归 14/14 通过；合成屏颜色辅助 100%、纯位置 96%；Kotlin 编译通过；真机安装回测未完成（设备离线）。
