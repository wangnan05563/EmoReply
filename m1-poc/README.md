## 这是什么

M1 概念验证的完整形态是「Android 通知监听捕获 → 云端 LLM 生成 → 输入法候选条注入」。
其中**捕获与交付依赖 Android 运行时和真机**，本机（Windows，无 Android SDK / adb / IM 应用）
无法闭环；本目录交付的是链路中**与平台无关**的部分，用参考实现 + 自动化测试把可验证的
验收准则先钉死，真机侧只需替换捕获层与 generator。

## 目录

```
m1-poc/
├── emoreply/
│   ├── models.py       # 通知载荷 / 判定结果 / 候选（对齐 FR-1.2 字段）
│   ├── preprocess.py   # 去重、噪声过滤、指向判定、空载荷兜底（FR-1.3/1.4/1.5）
│   ├── compose.py      # 伪历史拼装 + token 预算截断 + 提示词（FR-3.1 / C16）
│   ├── sanitize.py     # 输出清洗：md 符号 + HTML 标记（C3 / C25）
│   ├── guardrail.py    # 安全护栏 + 提示节流（FR-3.5/6.4 / C6）
│   └── pipeline.py     # 编排：捕获 → 预处理 → 生成 → 清洗 → 护栏 → 候选
└── tests/test_acceptance.py   # 按 FR 分节的验收测试
```
